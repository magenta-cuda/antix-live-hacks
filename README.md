# antix-live-hacks

I use antiX Live to run WordPress in a Docker container on a 4GB RAM machine which must also run a desktop (IceWM) and Firefox. These are the hacks I use to get Docker to work with very limited memory in a live environment.

Wordpress can be run without the Apache2 server and without the Mariadb server by using PHP's builtin server (-S option) and a Sqlite3 database. I think the most convenient way to do this is to use a Docker container with the pre-built image 'php:8.4-cli-alpine' or 'phpdebugger/php:8.4-cli-alpine'. The alpine version is significantly lighter then the standard version and if you do not use custom extensions then you probably won't have any problems with musl vs glib compatibility. If you want xDebug for debugging then the phpdebugger version which is a stripped down version of xDebug for debugging only (i.e., no profiling) is significantly lighter than the full xDebug version. This Docker configuration uses ~300MB.

Docker has a very large sparse file in /var/lib/docker. There are two problems for antiX Live with this. First, persist-save expands sparse files when they are copied from the tmpfs to the rootfs. Second, init also expands sparse files when they are copied from the rootfs to the tmpfs. The first problem is easily fixed by adding the -S option to rsync. The second problem is much harder to fix as init runs in the environment of initrd. In particular, cp is implemented by busybox which always expands sparse files. The solution recommended by AI is to replace busybox's cp with the glib version of cp which can preserve spareness. Unfortunately, compiling binaries is not in my current skill set so as a workaround I will fix init to skip the large sparse file and load it later when the more capable glib version of cp of the loaded filesystem is available.
